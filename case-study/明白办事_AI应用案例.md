# 明白办事：把政策文件翻译成一张能照着办的清单

**AI 应用开发案例 · 社区政策场景**

面向社区工作者、老年人和新市民。上传政策，几分钟生成一张明白卡：谁能办、能领什么、要带什么、怎么办、什么时候截止、常见坑，每条结论都能回到原文。

## a. 做了什么

**问题：** 政策不是没有，是看不懂、跑不完、答不过来。一份政策几千字，关键条件藏在附件和术语里；材料清单分散，居民少带一样就要再跑一趟；同一个问题，社区窗口每天要回答几十遍。

**功能：**

- 政策翻译：自动拆出谁能办、待遇标准、所需材料、办理流程、时限和注意事项。
- 原文可追溯：每条结论带 [n] 引用，展开即可核对原文。
- 两种视角：居民版用大白话；工作者版生成可直接转述的回复。
- 能落地：材料清单可勾选、导出 Markdown、打印；支持大字和浏览器朗读。
- 不串政策：问答锁定当前政策，回答只基于这份文件。

**使用流程：** 选政策 / 上传 → 生成明白卡 → 勾选材料 / 提问 → 导出或转述。

## b. 用了什么工具

**技术栈：** Python 3.13、FastAPI、SQLite、scikit-learn TF-IDF、原生 HTML/CSS/JS、SSE、ChatGPT / Claude Code 式 AI 编程。

**AI 辅助开发过程：**

1. 拆需求：用 AI 把 JD 和社区痛点拆成 6 个可验证的小任务：政策卡、引用、问答、上传、导出、适老化。
2. 生成骨架：让 AI 生成 FastAPI 分层、SQLite schema、SSE 路由和前端结构。
3. 人工审查：重点检查检索范围、引用映射、错误处理和敏感信息，不让 AI 直接上线。
4. 调试迭代：用 AI 解释中文检索零命中、SSE 断流和 CSS Grid 错位，再逐项验证。
5. 沉淀：把有效提示词、踩坑和测试记录写进文档。

**结构化抽取提示词示例：**

```text
角色：你是政策翻译助手。
目标：把政策片段改写成居民能照着办的清单。
约束：只依据片段；每条结论标注 [n]；
涉及金额、年龄、时限时提醒以官方为准。
输出：谁能办 / 要带什么 / 怎么办 / 何时截止 / 常见坑。
```

## c. 结果怎么样

| 指标 | 结果 |
| --- | --- |
| 示例政策 | 4 份 |
| 可追溯片段 | 12 个 |
| 本地问答响应 | 约 0.6-0.8 秒 |
| 平均材料清单 | 3-7 项 |
| 平均办理流程 | 3-6 步 |
| 预计节省 | 约 128 分钟（演示估算） |
| 端到端验证 | 桌面 1440px 与手机 390px 均无横向溢出，0 控制台报错 |

> 估算口径：人工整理 30 分钟 / 政策、助手 5 分钟；人工问答 6 分钟、助手 0.5 分钟。测试环境无外网，使用本地 TF-IDF 兜底。实际效果需在社区试点中验证。

## 面试可讲的技术点

- 中文检索用字符 n-gram TF-IDF，离线可跑，不依赖向量库。
- 问答锁定 doc_id，片段按原文顺序编号，引用和来源一一对应。
- 口语问句零命中时，回退当前政策全文，再按意图抽字段。
- SSE 流式输出，模型不可用时自动降级到本地检索。
- 结构化抽取：标题 / 列表启发式 + 字段关键词 + 引用映射。
- 前端：双边框卡片、响应式单列、大字模式、浏览器朗读、打印与 Markdown 导出。
